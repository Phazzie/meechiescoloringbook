What this proves that the unit tests cannot:

1. The gate is reached through the real SvelteKit request path, not only
   through an injected dependency in a test.
2. RateLimit-Remaining decrements exactly once per request and the 21st
   request in the window is denied — the budget is 20, enforced.
3. Retry-After is present on denial and derived from the store's reset
   rather than recomputed by the route.
4. The charge happens BEFORE the provider call: every one of the first 20
   requests was charged even though the provider then failed. A caller
   cannot burn quota-free provider attempts by making the provider fail.
5. E1's public provider-error boundary holds on the same path: the
   provider failure surfaces as MEECHIE_TOOL_PROVIDER_ERROR with no
   upstream message, URL, or credential crossing the boundary, and as a
   502 rather than the 200 it used to return.

Degraded (in-process) store was active, since no durable Upstash settings
are configured in this environment. That is the documented behaviour for a
fully-unconfigured deployment and is still metered.
