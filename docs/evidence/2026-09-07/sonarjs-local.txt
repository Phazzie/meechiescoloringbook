## First run - three findings, all in this PR's own new code

src/lib/core/print-sheet.ts
  71:1   warning  Unused eslint-disable directive (no problems reported from 'no-control-regex')
  88:12  error    sonarjs/super-linear-regex   /[. ]+$/
  96:25  error    sonarjs/super-linear-regex   /[.,;:\-\s]+$/

## Disposition

Both errors were real and both were mine. `X+$` is the shape that backtracks super-linearly on a
long run of the matched characters, and a page title is attacker-adjacent input - it comes back
from a model. Replaced with `trimTrailing`, a backwards scan over a `Set`, which is also clearer
about what it removes and why.

The warning is a FALSE POSITIVE of the reproduction, not a finding: this throwaway config enables
only `sonarjs.configs.recommended.rules`, which does not include core ESLint's `no-control-regex`.
The repo's own config DOES enable it, and removing the directive turns `npm run lint` red:

  src/lib/core/print-sheet.ts
    71:26  error  Unexpected control character(s) in regular expression: \x00, \x1f  no-control-regex

So the directive is load-bearing and was restored, with that reason written beside it. Recorded
here because "the checker said it was unused" is exactly the kind of finding a later run would
otherwise re-derive and act on wrongly.

`tail`'s exit code and printed `lint=0` over a real eslint error. Run 12 recorded this exact trap
for `test:e2e` and it caught this run anyway, one command over. Capture to a file and read `$?`.
