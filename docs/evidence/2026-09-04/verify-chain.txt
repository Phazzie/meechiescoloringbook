## Why lint.txt and build.txt were re-run for a documentation-only commit

The first push of this close-out left them as they were, on the argument that the src/ and tests/
trees are byte-identical to the merge commit those artifacts already describe, and that a fresh
timestamp over unchanged output is not evidence of anything.

Codex raised it as a P1 and is right, for a reason the argument missed. AGENTS.md requires
`npm run check`, `npm run lint`, `npm test` and `npm run build` **before every push** — the rule is
about the head being pushed, not about whether the inputs are believed to have changed. An artifact
that predates the head cannot prove the head passed, however sound the reasoning is that it would.
"I am sure it still passes" is a claim; running it is a measurement. Both were re-run and both pass.

## Why proof-tape.md still marks lint.txt and build.txt as PREDATES THIS VERIFY RUN

Because they always will be, and this corrects a claim the previous verify-chain.txt made.

`markArtifactsPredatingRun` in scripts/proof-tape.mjs takes its marker from the mtime of
chamber-lock.json, which is written by **stage 2 of the chain**. lint and build are not stages of
the chain, so whichever side of it they are run on they cannot come out fresh: run before, they
predate the marker; run after, they postdate it but proof-tape.md was already rendered at stage 8
and does not see them. The previous run's note — "run after the chain so they postdate its marker"
— was wrong about the second half.

The marker means "not produced by this chain", not "stale". Their own content is the evidence:
lint.txt and build.txt in this folder were produced from this exact head, minutes before the chain
ran.

## Why e2e.txt does predate this run, in the ordinary sense

`npx playwright test` is required by AGENTS.md "when the change is user-facing". This commit changes
a log file and this folder; nothing it touches reaches a browser, so the suite was not re-run and
e2e.txt is left describing the head it was produced from — cccf0c2, whose src/ tree is this one.
The 22-passing result recorded there is the result for the code that ships.
