## Why lint.txt and build.txt were re-run for a documentation-only commit

The first push of this close-out left them as they were, on the argument that the src/ and tests/
trees are byte-identical to the merge commit those artifacts already describe, and that a fresh
timestamp over unchanged output is not evidence of anything.

Codex raised it as a P1 and is right, for a reason the argument missed. AGENTS.md requires
`npm run check`, `npm run lint`, `npm test` and `npm run build` **before every push** — the rule is
about the head being pushed, not about whether the inputs are believed to have changed. An artifact
that predates the head cannot prove the head passed, however sound the reasoning is that it would.
"I am sure it still passes" is a claim; running it is a measurement. Both were re-run and both pass.

## How to make proof-tape.md see them, and a correction to two earlier claims

`markArtifactsPredatingRun` in scripts/proof-tape.mjs takes its marker from the mtime of
chamber-lock.json, written at **stage 2** of the chain. Two claims about that have now been wrong in
this folder:

  - The previous run's note said running lint and build *after* the chain makes them postdate the
    marker. Half true: they do postdate it, but proof-tape.md was already rendered at stage 8 and
    does not see them, so the tape still marks them.
  - This file's own previous revision then concluded they can therefore **never** come out fresh.
    That is also wrong, and Codex named the fix: run them after the chain and then invoke
    `npm run proof:tape` on its own. chamber-lock.json keeps its stage-2 mtime, the standalone
    artifacts are newer than it, and the re-rendered tape reports them as current.

That is the order used here, and lint.txt and build.txt now carry no marker.

A note on the shape of that mistake, since this run's log entry is about exactly it: the first claim
was inherited from the previous run's file and repeated without testing. The second was reasoned
from the source and stated as an impossibility after one attempt. Reading the code is not the same
as running it either.
