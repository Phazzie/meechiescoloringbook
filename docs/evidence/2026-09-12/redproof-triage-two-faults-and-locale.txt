Red-proof: round 15's four findings on caba989, each reintroduced and each caught
=================================================================================

Findings, in substance:

  1. Reject malformed rows before parsing their PR cells. A row with BOTH faults at once —
     `| 348 | title |`, too narrow AND missing its `#` — passed every guard. `findRowsWithBadPrCell`
     skipped it (it only judges full-width rows), `readTable` left it out of prRows (the cell does not
     parse), and `findMalformedRows` only inspected prRows. Two checks that each catch one fault, and
     a row carrying both fell between them: the analyzer advanced the provenance line having never
     measured that PR, and the validator reported an empty backlog. Reproduced before the fix:

         prRows            [{"pr":348,"lineIndex":3}]
         badPrCell         []
         malformed         []
         validateTable     {"ok":true}

  2. Honor adaptive fence lengths in the conflict-block assertion. The test helper that reads the
     committed block back toggled its own `/^`{3,}/` flag, which a file named exactly ``` satisfies —
     so it read the surrounding markup as paths and would have failed `npm test` on a valid refresh.
     The production reader had been fixed for that one round earlier; the reader that checks it had not.

  3. Sort conflict summaries independently of host locale. `summarizeConflictPaths` used
     `localeCompare` with no locale, so the same git measurement wrote a different committed table
     depending on the machine: `sv-SE` orders `ä` after `z`, `en-US` before it. A file whose bytes
     depend on where they were generated is not evidence, and the idempotence this script is proved to
     have held only per machine.

  4. Resolve PR rows by column name in committed-table tests. Those assertions used
     `/^\|\s*#\d+\s*\|/` — the first-column assumption the production parser was fixed for two rounds
     earlier — so moving the `PR` column would leave them finding no rows and failing, blocking a
     schema change the readers support.

Fixes: width is now checked over every non-divider row of the contiguous table and checked FIRST,
because it needs no parsing (`findMalformedRows(lines, headerIndex)`); `fencedLines` returns a
classification (`outside` / `open` / `inside` / `close`) so the marker scan and the block reader share
one implementation of the CommonMark rule; ordering is by UTF-16 code unit; and the committed-table
assertions resolve rows through `readTable`.

Each mutation below reintroduces one defect and runs
`npx vitest run tests/unit/analyze-merge-conflicts.test.ts`.
