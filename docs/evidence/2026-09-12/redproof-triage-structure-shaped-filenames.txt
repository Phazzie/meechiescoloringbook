Red-proof: round 14's five findings on 02ef91e, each reintroduced and each caught
=================================================================================

Three of the five are defects the previous round's own fix created — the lossless block writes
arbitrary filenames into the file this script also reads for structure — and that is the finding
worth stating plainly:

  **A writer that emits arbitrary content into a file its own reader parses has handed the reader's
  grammar to whoever names the content.** A conflicted filename can be `| #999 | ... |`, or exactly
  `<!-- conflicting-paths:begin -->`, or `   `. Each was read as structure rather than as content.

Findings, in substance:

  1. Stop parsing at the end of the PR table (analyze-merge-conflicts.js). readTable and
     findRowsWithBadPrCell scanned to EOF, so a filename shaped like a data row — legal, and now
     written verbatim into the block below the table — became a PR row. The analyzer would fetch a
     pull request that does not exist, or rewrite that filename inside the fence.
  2. Reject duplicate provenance lines before refreshing. validateTable checked that at least one
     exists; rewriteProvenance updates the first. Two lines meant one refreshed and one left
     claiming a different base, exit 0.
  3. Keep marker-shaped filenames from becoming block delimiters. A file named exactly
     `<!-- conflicting-paths:begin -->` was written into the fence and then counted as a second
     marker, so a refresh that succeeded produced a table the next run refuses to read.
  4. Compare summaries without splitting valid filenames (the test). The real-file check split the
     cell on comma-space, so a file named `a, b.md` — written correctly into both the cell and the
     block — read as two entries and failed `npm test`, making a valid refresh impossible to commit.
  5. Preserve filenames made entirely of whitespace. parseConflictPaths tested its terminator on a
     trimmed copy, so a file named `   ` read as the empty separator before git's diagnostics: the
     table recorded that git named no files and the path was missing from the block as well.

Fixes: row discovery is bounded to the contiguous table (`tableRowEnd`); marker discovery skips
fenced lines, with CommonMark's closing rule so a shorter backtick run cannot close a longer fence
(`fencedLines`); exactly one provenance line is required, as for the block markers; the real-file
check now *generates* the cell from the block's paths with `summarizeConflictPaths` and compares,
parsing no filenames at all; and the path terminator is an empty line rather than a blank one.

Each mutation below reintroduces one defect and runs
`npx vitest run tests/unit/analyze-merge-conflicts.test.ts`.
